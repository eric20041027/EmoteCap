# Paired local receiver

Local candidate0.2.0targets Windows/Unity6000.5.9f1. Exact runtime dependency: official com.unity.nuget.newtonsoft-json3.2.2(Newtonsoft.Json13.0.2). The historical unpaired0.1.0consumer is incompatible with the paired service.2021.3and other Editor/platform/player targets are unqualified.

Use a Humanoid Avatar and its bind/T-pose; an Animator Controller overrides live poses and should be removed. Add EmoteCapLiveLink, run EmoteCap and enable Studio Live Link. Enter Unity Play mode first, paste the current80character code in the receiver Inspector, then Connect. The input disappears after use. Scene/prefab/domain reload never retains it. Do not place pairing credentials in scripts/assets/logs; runtime integrations may call ConnectPairing with an in-memory code and StopPairing explicitly.

The supported endpoint is loopback on this computer (localhost/127.0.0.1/::1, port8787by default). Status distinguishes connecting, waiting for Studio/source frames, receiving, reconnecting, invalid code/Avatar/endpoint and pairing rejection. Five-second handshake timeout, expired/revoked/incompatible pairing stops retry; normal disconnection waits2seconds before reconnecting. Stop/disable/destroy/new Connect invalidate old callbacks before closing their owned resources. Missing source holds the last displayed pose. Invalid target arithmetic preserves the previous pose; check target scale/bind pose before reconnecting. Invalid Avatar/hips requires assigning a valid Humanoid; unrelated Editor/player compatibility is not inferred.

Motion remainsv2with48driven bones/192quaternion values. Timeline uses double precision and may exceed180seconds. Frames require finite values, canonical in-place hips, unit quaternion tolerance and increasing time per source; new/null source announcements reset pending data. Entire UTF-8messages are bounded16KiB; binary/coerced/duplicate/deep/non-JSON input cannot reach transforms. Status text does not echo peer data or credentials.

Actual Editor qualification uses an isolated local-UPM project with testables for com.emotecap.mocap and exact TestFramework1.7.0/Newtonsoft3.2.2/NUnit2.1.0. Use the repository's scripts/test-unity.ps1 for owned fresh EditMode results. Whole PlayMode including real relay requires scripts/unity-relay-test.py, which starts an owned loopback fixture server, passes its URL to the actual Editor, runs controlled and real ClientWebSocket tests and closes its own service. Paths/results remain inside the ignored Unity-plan workspace; prior evidence is retained. It uses synthetic original test rigs/frames and no camera/provider. These checks do not substitute for two public sample rigs, actual FBX playback, authorized motion/video, target laptop or beginner acceptance.
