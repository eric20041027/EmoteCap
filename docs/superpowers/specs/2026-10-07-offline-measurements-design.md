# Offline measurement receipts for M4

The product design requires actual authorized before/after video quality and target-laptop Fast720p measurements. Build the offline arithmetic/validation tools and collection protocol now, while owner input and hardware are pending. This increment must never be presented as the real baseline or product acceptance. It does not start cameras/models, grant SDK permission, upload, change the solver or add application instrumentation.

An `emotecap-measurement-v1` packet records UUID runId, full40hex sourceCommit, synthetic/observed classification, local-processing rights declaration, inputSHA256, sourceKind video/camera, environment kind/os/cpu/gpu/browser, settings quality/dimensions/crop/smoothing/skeleton/sdkVersion/modelSha256/delegate/handPolicy, performance-monotonic clock, a named detection-to-solver latency definition, actual start/end/warmup milliseconds, all attempted samples and explicit annotations. Unknown/private fields are rejected. A packet is at most32MiB,21601samples,180seconds; every number is finite, times ordered, wall attempts nonoverlapping and inside the measured window. Sample statuses are ok/no-pose/detector-error/solver-error; only ok has a canonical v2 MotionFrame, with frame.t matching inputTimeS. Reuse the existing MotionFrame validator and bones contract. Rights/environment fields are operator declarations, not independently verified grants/hardware evidence.

Exclude attempts starting before declared warmup ends. EffectiveFPS is successful attempts divided by the full remaining actual wall interval, including idle/dropout time. Attempt failure rate retains every measured no-pose/error attempt. Nearest-rank p95 includes durations of all measured attempts and is named detection-to-solver duration, not camera-to-display latency. No attempts => null failure rate/p95; no successful attempts =>0successfulFPS and unavailable quality metrics. Retain overall status counts/warmup counts. Do not derive failure rate from a saved success-only take or UI EMA.

Annotations are at most32unique named intervals: stationary (all driven bones) or left/right stance. Bounds use input seconds and must fit the observed input timeline. Stationary quaternion angular departure from each interval's first valid frame is normalized and sign invariant; report per-bone RMS degrees and valid/attempt coverage, unavailable with fewer than2valid samples. Canonical heel horizontal path in meters uses the committed skeleton/world-delta FK plus in-place hips, sums only adjacent ok attempts inside a stance interval, and never bridges a no-pose/error. Report valid pair and sample coverage; unavailable without a pair. This is an in-place contact-drift proxy, not anatomical accuracy or ground-truth foot sliding. No quality threshold or improvement assertion is invented.

Comparison requires distinct run IDs, identical input identity/source kind/classification, environment, settings, clock/latency definition/warmup and annotations. Different actual wall lengths can be normalized, but mismatched conditions are rejected. Keep source commits, raw-packet SHA256, evaluator source/contract/lock digests, summaries and arithmetic deltas with null propagation. No synthetic/observed mixing or PASS/release-ready field.

CLI input/baseline must be ordinary bounded nonlinked/nonhardlinked files with duplicate-free strict JSON; output must be a fresh ordinary location, exclusive creation, never overwrite input or an existing report. Print only a compact status/count. Preserve raw inputs and prior reports. No dependencies/public/main/license/package runtime changes. Tests use owned synthetic analytic controls. A separately supplied real capture protocol is still needed; saved takes lack all failure/timing attempts. Actual SDK consent/network, authorized recordings, target laptop, Unity/two rigs, clean-machine/new-users and rights remain pending.
